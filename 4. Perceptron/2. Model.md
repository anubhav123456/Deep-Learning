# Perceptron Model – Model 

---

## 1. Perceptron Recap

The Perceptron has:

* **Input:** Real-valued features
* **Output:** Boolean (0 or 1)
* **Task:** Binary Classification

Example:

Phone Features:
* Price
* Screen Size
* Battery
* RAM
* Weight

$$\downarrow$$

Perceptron

$$\downarrow$$

Output:
* 1 → Like / Buy
* 0 → Don't Like / Don't Buy

---

## 2. Structure of the Perceptron

The Perceptron looks almost the same as the MP Neuron.

The main differences are:

| MP Neuron | Perceptron |
| :--- | :--- |
| Boolean inputs (0/1) | Real-valued inputs |
| Boolean output | Boolean output |
| Fixed weights | Learnable weights for every feature |

Every input has its own weight:

```text
x1 ---- w1 \
x2 ---- w2  \
x3 ---- w3   ---> Weighted Sum ---> Decision ---> Output
...          /
xn ---- wn /
```

---

# 3. Perceptron Decision Rule

The Perceptron computes the **weighted sum** of all inputs:

[
w_1x_1+w_2x_2+\cdots+w_nx_n
]

Then compares it with a threshold (b).

### If

[
w_1x_1+w_2x_2+\cdots+w_nx_n \ge b
]

Output

[
\hat y=1
]

Otherwise

[
\hat y=0
]

---

## In simple words

1. Multiply every feature by its weight.
2. Add all the results.
3. Compare with the threshold.
4. Decide:

   * Above threshold → **1**
   * Below threshold → **0**

---

# 4. Why Do We Need Weights?

Different features influence the decision differently.

Weights tell the model:

* Which feature is more important.
* Whether a feature helps or hurts the decision.

---

## Example 1: Price

Suppose

* Higher price → Less likely to buy

As price increases:

```
Price ↑
```

the weighted sum should decrease.

This is possible only if

[
w_{\text{price}}<0
]

So **Price gets a negative weight.**

Example:

Price = ₹10,000

Weight = -2

Contribution

```
(-2) × 10000 = -20000
```

Large price → Large negative contribution → Harder to cross the threshold → Output likely becomes **0**.

---

## Example 2: Screen Size

Suppose you like larger screens.

As screen size increases,

the weighted sum should also increase.

So

[
w_{\text{screen}}>0
]

Example

Screen = 6.5 inches

Weight = +3

Contribution

```
3 × 6.5 = 19.5
```

This increases the weighted sum, making it easier to cross the threshold.

---

# 5. Interpretation of Weights

| Weight          | Meaning                                    |
| --------------- | ------------------------------------------ |
| Positive        | Feature increases the chance of output = 1 |
| Negative        | Feature decreases the chance of output = 1 |
| Large magnitude | Feature is more influential                |
| Small magnitude | Feature has less influence                 |

---

# 6. Representing Data as Vectors

Instead of writing every feature separately,

represent the phone as a vector:

[
\mathbf{x}
==========

[x_1,x_2,x_3,\dots,x_n]
]

where

* (x_1) = Price
* (x_2) = Screen Size
* (x_3) = Battery
* ...
* (x_n) = Last feature

Similarly,

weights become another vector:

[
\mathbf{w}
==========

[w_1,w_2,w_3,\dots,w_n]
]

---

# 7. Dot Product

The weighted sum

[
w_1x_1+w_2x_2+\cdots+w_nx_n
]

is exactly the **dot product** of the input vector and the weight vector:

[
\mathbf{x}\cdot\mathbf{w}
=========================

\sum_{i=1}^{n}w_ix_i
]

This provides a compact mathematical representation of the Perceptron.

---

# 8. Compact Perceptron Rule

Using the dot product, the Perceptron can be written as:

[
\hat y=
\begin{cases}
1, & \text{if } \mathbf{x}\cdot\mathbf{w}\ge b\
0, & \text{otherwise}
\end{cases}
]

where:

* (\mathbf{x}) = Input vector
* (\mathbf{w}) = Weight vector
* (b) = Threshold (bias)

---

# 9. Geometric Interpretation

The decision boundary is given by:

[
w_1x_1+w_2x_2+\cdots+w_nx_n-b=0
]

This equation represents:

* A **line** in 2D.
* A **plane** in 3D.
* A **hyperplane** in higher dimensions.

Classification:

* **On or above the hyperplane** → Output = 1
* **Below the hyperplane** → Output = 0

The Perceptron essentially learns this separating hyperplane to distinguish between the two classes.

---

# Key Takeaways

* The Perceptron accepts **real-valued inputs** and produces a **Boolean output**.
* Each input feature has a **learnable weight**.
* The model computes a **weighted sum** of all input features and compares it with a threshold.
* **Positive weights** increase the likelihood of output = 1, while **negative weights** decrease it.
* The weighted sum can be written compactly as the **dot product** (\mathbf{x}\cdot\mathbf{w}).
* The Perceptron decision rule is:

[
\hat y=
\begin{cases}
1, & \mathbf{x}\cdot\mathbf{w}\ge b\
0, & \text{otherwise}
\end{cases}
]

* Geometrically, the Perceptron learns a **line/plane/hyperplane** that separates the two classes.

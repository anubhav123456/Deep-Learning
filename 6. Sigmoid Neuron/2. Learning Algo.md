# **From Guesswork to a Principled Learning Algorithm**

In this lecture, the instructor transitions from the trial-and-error guesswork approach to a systematic, vector-based framework for updating model parameters. This sets up the foundational math behind modern optimization algorithms like **Gradient Descent**.

---

## 1. Goal of the Learning Algorithm

So far, we have established:

* **Data:** Inputs ($x$) and outputs ($y$)
* **Task:** Binary classification or probability regression
* **Model:** Sigmoid function
* **Loss:** Squared Error Loss

Now, the objective is:

> **Find the parameters $w$ and $b$ automatically so that the loss becomes as small as possible.**

---

## 2. What We Want to Learn

The sigmoid model is:

$$\boxed{\hat{y} = \frac{1}{1 + e^{-(wx + b)}}}$$

Different values of $w$ and $b$ produce different sigmoid curves. The objective is to find the best values of $w$ and $b$ such that:

* Predicted outputs are close to true outputs.
* Total loss is minimized.

---

## 3. Guesswork Isn't Enough

Earlier, the instructor manually changed parameters (increasing $w$, decreasing $b$) and observed whether the sigmoid curve matched the data better.

This worked only because:

* There was only one input feature.
* The graph could easily be visualized in 2D/3D.

In real-world datasets:

* Hundreds or thousands of parameters exist.
* Visualizing the loss surface is impossible.
* Manual guessing cannot scale.

Therefore, we need a formal mathematical algorithm.

---

## 4. How Optimization Works in Practice

Modern Machine Learning frameworks like **PyTorch** and **TensorFlow** perform this optimization automatically under the hood. As a programmer, you typically specify:

* The **Model** (e.g., Sigmoid)
* The **Loss Function** (e.g., Squared Error)
* The **Optimizer** (e.g., Gradient Descent)

The framework automatically updates $w$ and $b$. Studying this logic reveals what these frameworks are doing internally.

---

## 5. Combining Parameters into One Vector

Instead of treating $w$ and $b$ separately, we combine them into a single **parameter vector**:

$$\boxed{\boldsymbol{\theta} = \begin{bmatrix} w \\ b \end{bmatrix}}$$

This notation simplifies the math: instead of asking *"How do we find $w$ and $b$?"*, we ask *"How do we find the optimal vector $\boldsymbol{\theta}$?"*

---

## 6. Updating Parameters

Learning means repeatedly updating parameters. Instead of updating $w$ and $b$ individually:

$$w \leftarrow w + \Delta w$$

$$b \leftarrow b + \Delta b$$

We write a single vector update rule:

$$\boxed{\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \boldsymbol{\Delta\theta}}$$

where:

$$\boldsymbol{\Delta\theta} = \begin{bmatrix} \Delta w \\ \Delta b \end{bmatrix}$$

This represents moving from the current state to a slightly better parameter state.

---

## 7. Vector Interpretation

Think of $\boldsymbol{\theta}$ as a point (or vector) in parameter space:

* **Current Position:** $\boldsymbol{\theta}$
* **Desired Movement:** $\boldsymbol{\Delta\theta}$
* **New Position:** $\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \boldsymbol{\Delta\theta}$

Rather than taking massive jumps, the learning process moves by taking small, controlled steps.

---

## 8. Learning Rate ($\eta$)

Rather than moving by the entire magnitude of $\boldsymbol{\Delta\theta}$, we scale the step size using a parameter called the **learning rate** ($\eta$):

$$\boxed{\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \eta \boldsymbol{\Delta\theta}}$$

where $\eta$ (eta) is a small positive scalar.

**Typical values for $\eta$:** $0.1$, $0.01$, or $0.001$.

### Why Use a Learning Rate?

* **Without $\eta$:** Large steps can overshoot the optimal minimum.
* **With $\eta$:** Small, safe steps allow the parameter updates to converge smoothly.

---

## 9. Meaning of Learning Rate

The learning rate controls the step size of each parameter update:

* **Small Learning Rate:** Very safe and stable, but learning is slow.
* **Large Learning Rate:** Faster updates, but risks overshooting or failing to converge.

---

## 10. The Core Challenge

We have established the update rule:

$$\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \eta \boldsymbol{\Delta\theta}$$

We choose the hyperparameter $\eta$, but we still need a way to determine $\boldsymbol{\Delta\theta}$.

> **The Big Question:**
> Which direction should $\boldsymbol{\Delta\theta}$ point so that the loss consistently decreases?

---

## 11. Desired Property: Monotonic Decrease in Loss

After every update step $t$, we want:

$$\boxed{\mathcal{L}(\boldsymbol{\theta}_{t+1}) < \mathcal{L}(\boldsymbol{\theta}_t)}$$

Every step should reduce the loss, creating a smooth downward trajectory toward the minimum rather than the fluctuating losses seen with guesswork:

$$\text{Fluctuating Loss (Guesswork): } 0.15 \rightarrow 0.08 \rightarrow 0.12 \rightarrow 0.05 \rightarrow 0.09$$

$$\text{Monotonic Decrease (Ideal): } 0.15 \rightarrow 0.11 \rightarrow 0.07 \rightarrow 0.04 \rightarrow 0.01 \rightarrow 0$$

---

## 12. What's Coming Next?

The missing piece of the puzzle is:

> **How do we mathematically compute $\boldsymbol{\Delta\theta}$?**

The answer comes from calculus using **derivatives and gradients**, leading directly to the **Gradient Descent** algorithm.

---

## Summary Table

| Concept | Description | Formula |
| --- | --- | --- |
| **Parameter Vector** | Combined weight and bias vector | $\boldsymbol{\theta} = [w, b]^T$ |
| **Update Vector** | Direction and scale of change | $\boldsymbol{\Delta\theta} = [\Delta w, \Delta b]^T$ |
| **Learning Rate** | Step-size scaling factor ($\eta$) | Typically $0.1, 0.01, 0.001$ |
| **Update Rule** | Parameter update step | $\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \eta \boldsymbol{\Delta\theta}$ |
| **Objective** | Ensure loss decreases monotonically | $\mathcal{L}(\boldsymbol{\theta}_{\text{new}}) < \mathcal{L}(\boldsymbol{\theta})$ |

---

## Key Takeaways

* The goal is to learn the best $w$ and $b$ that minimize the loss function automatically.
* Manual guesswork is impractical for multi-dimensional real-world datasets.
* Frameworks like PyTorch and TensorFlow handle optimization automatically, but understanding the underlying vector math is essential.
* Combining parameters into a single vector $\boldsymbol{\theta} = [w, b]^T$ simplifies parameter updates.
* Parameters are updated iteratively using:

$$\boldsymbol{\theta}_{\text{new}} = \boldsymbol{\theta} + \eta \boldsymbol{\Delta\theta}$$

* The learning rate ($\eta$) controls the size of each update step to prevent overshooting.
* The remaining challenge is calculating the precise direction vector $\boldsymbol{\Delta\theta}$, which forms the foundation of **Gradient Descent**.
